Where the money goes

Spend by model. The router selects on price — concentration here is a routing decision, so it should be explainable.

Cache economics by model

read tokens write tokens

Reads at ~0.1× are the payoff; writes are the premium paid to get there. Reads pinned at zero on a busy model = broken caching.

Cost-estimate drift by model

Signed mean of (estimate − actual) ÷ actual. Budget enforcement trusts the estimate; drift here is enforcement quietly going wrong.

Routing misses

Quality checks failed on an OK response — evidence the (model, intent) pairing is wrong, and what the reputation loop feeds on.

Query it yourself

The record database is plain SQLite — one table, records, one row per request.

sqlite3 var/records.db "SELECT chosen_model, ROUND(SUM(actual_cost_usd),4) AS usd,
  SUM(cache_read_tokens) AS cached FROM records GROUP BY 1 ORDER BY usd DESC"

duckdb -c "SELECT resolved_intent, COUNT(*), AVG(latency_total_ms)
  FROM sqlite_scan('var/records.db','records') GROUP BY 1"

python -m aigateway.replay.harness var/records.db   # counterfactual routing costs
