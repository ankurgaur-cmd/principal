How this works — and what you need to provide

The flow. Your agent sends an ordinary OpenAI-shaped request with model: "auto". The gateway classifies what the request is for, works out the smallest model tier that can do it, prices every qualifying model for this specific request — including what the prompt cache would cost or save on each — and sends it to the cheapest one. It records every hop on the way.

You provideWhy it matters
API key
required		 At least one vendor key, in the panel below. Nothing can be served without it — routing still works, calls do not.
session_id
strongly advised		 Groups the turns of one workflow. This is what lets the gateway keep a prompt cache warm; without it every request is a cold start and you lose most of the saving.
Shared context
optional		 The stable part of your prompt — system instructions, tool definitions, retrieved documents. The bigger and more stable it is, the more caching is worth.
intent
optional		 If your agent already knows the task type, saying so skips classification entirely. Cheapest possible path.
Budget / RPM
optional		 Per-tenant caps. Over budget, the router degrades to a cheaper tier and says so, rather than cutting you off.

Reading the dashboard. Pipeline shows one request moving through the gateway. Why this model explains that choice in plain English. Fleet aggregates every request to show where your traffic and spend actually go. Transaction trace lists every server this one request touched. Model pool is the live health of each model.
